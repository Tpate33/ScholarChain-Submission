**Defects found (owner: `hadoop-engineer`):**

- **D1, medium – a record inside an XML comment becomes a work.**
  - Input: `xml/comment.xml`, where `<article key="journals/adv/Ghost">…</article>` sits inside a `<!-- … -->` longer than one split, read with 64-byte splits.
  - Expected: Ghost is never a work, because commented-out text is not a record.
  - Observed: with 64-byte splits, `journals/adv/Ghost` is accepted as a work. With whole-file reading it is correctly skipped.
  - Suspected cause: `DblpInputFormat.scala:84-111` (`DblpScanner.next`). A scanner that starts mid-file treats the first `<article` it sees as a record start, without knowing it is inside a comment. Its ownership-rule comment at lines 47-52 assumes this can't happen. This was the known "unverified" risk; it is now confirmed.
  - Failing test: "an XML comment containing a record tag never yields a work (64-byte splits)".

- **D2, medium – an unclosed record swallows the valid records after it.**
  - Input: `xml/unclosed.xml`, where `<article key="journals/adv/Unclosed">` has no end tag and is followed by `conf/adv/Good4` and `journals/adv/Good5`.
  - Expected: the unclosed record is rejected and Good4 and Good5 are accepted.
  - Observed: with whole-file reading, Good4 and Good5 are silently lost and `INPUT.dblp` is 20. With 64-byte splits they survive, because they start in later splits. Production splits (about 128 MB) behave like the whole-file case.
  - Suspected cause: `DblpInputFormat.scala:162-178` (`readRecord`). It reads until the first `</article`, even across another record's start tag (`<inproceedings`, `<article`).
  - Failing test: "an unclosed record does not swallow the valid records that follow it (whole-file split)".

- **D3, medium – output depends on split size (a consequence of D1 and D2).** Works, mentions, rejects and `INPUT.dblp` differ between the 64-byte and whole-file runs. That breaks the README rule "Deterministic outputs for deterministic inputs" (README:1166) and the requirement that the reader synchronize on complete top-level records (README:2243). Failing test: "normalize output does not depend on the input split size (determinism)".
