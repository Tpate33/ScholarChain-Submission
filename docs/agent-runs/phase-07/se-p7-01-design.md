## Design summary
- Packages `scholarchain.storage.{port, model, load, fake, parquet, aws.s3, aws.dynamodb, aws.s3vectors, aws.neptune}`. Only `parquet` sees Parquet/Hadoop; only `aws.*` see the SDK. Fakes in main (so rag/services tests can use them).
- Ports: RunSource, PartReader[A], ObjectReader/ObjectWriter (putCreateOnce), GraphReader (runtime, template allowlist) / GraphLoader (batch), KeyValueReader (get/query, never Scan) / KeyValueWriter (putIfAbsent, putIfVersion), VectorReader / VectorWriter / IndexInspector, Embedder (fake in Phase 7), Clock/Sleeper/Jitter. Outcomes `Written | AlreadyPresent`; `StoreError` = Transient | Permanent | Conflict | StaleVersion | Corrupt | Refused. `RuntimeStores` exposes no loader or analysis-table writer (type test).
- S3: zone→bucket and prefixes from config; versioned keys by runHex/loadHex; create-once with If-None-Match plus ChecksumSHA256, 412 → head compare → AlreadyPresent or Conflict; ArtifactRegistry row per object; storage never deletes.
- Neptune: CSV `~label` equals core labels (6 vertex, 6 edge); DERIVED_FROM/SUPPORTED_BY listed as not produced by the implemented model and refused; byte-exact headers, RFC 4180, row counts equal manifest, StableId checks, duplicate `~id` and dangling endpoints refused; IDs copied verbatim and compared with Spark `graph-nodes`/`graph-edges` (459 nodes, 799 edges); bulk-load requests built not sent (vertices, then edges depending on the vertex job); one run per graph (`serving#neptune`); endpoint validation (https, neptune.amazonaws.com, Region, 8182; runtime uses `cluster-ro-`); closed openCypher template enum with typed parameters, no write keywords.
- Evidence trace (gate L1428): COAUTHORED_WITH.sourceEvidence → exactly one CoauthorEdgeV2 with the same pair/window/count/years; supportingWorkIds.size = jointPublicationCount; each supporting work AUTHORED by both endpoints.
- DynamoDB: string pk/sk; tables RunLedger, ArtifactRegistry, EvidenceBundle (no TTL), QuerySession and EntityLinkCache (TTL expiresAt), ResearcherMetricCache (justified, no TTL; 12 roles, 1,302 rows; GSIs byGroup, byPair, rank). Conditional writes: attribute_not_exists + ALL_OLD on failure → equal recordSha256 = AlreadyPresent, different = Conflict; putIfVersion → StaleVersion; BatchWriteItem never used for loads.
- S3 Vectors: five-index registry (researcher-profile-v1 ← researcher-profile; collaboration-community-v1 ← community-summary; collaboration-path-v1 ← path-summary and collaboration-summary (provisional); paper-abstract-v1 ← work-summary, no work-abstract rows this run; topic-institution-summary-v1 ← topic-summary, no institution rows this run). 249 source documents (236 + 13). Key = ChunkId.ofTextHash(subject, index, docType, textSha256); GetVectors compare before put; compact filterable metadata (documentType, subjectId, runId, indexVersion, sourceDataset, inputSources, researcherIds, windowStart/End, communityId, topicIds, institutionIds); non-filterable textS3Key, textSha256, modelVersion, loadId, inputId, schemaVersion; per-value cap refuses long text; batch 100 (≤ UNVERIFIED 500); full-jitter backoff 200 ms base, 20 s cap, 6 attempts, SDK retries off; permanent batch failure bisected; rejected-record schema `scholarchain.storage.rejected-record.v1` to RunLedger and `reports/loads/<loadHex>/rejects/`. Phase 7 stages documents (`documents-staged`); Phase 8 embeds; tests use a deterministic fake Embedder.
- Loader flow: decode load manifest → observe run directory, require `_SUCCESS` → `PartManifests.verify` → run manifest check → `checkAgainst` → role checks → decode and validate every row and cross checks → RunLedger publication/load rows → create-once/conditional writes. Rerun of a `loaded` load = zero writes; resume replays with AlreadyPresent.
- Tests: 18 suites (fixture integrity, load verification, Neptune CSV, graph load plan, evidence trace, query templates, fake graph, table specs, conditional writes, Dynamo load, Parquet reader, S3 layout, vector registry, vector metadata, vector batch/retry, serialization, run-ledger states, provenance).
- Increments: 1 model/ports/fakes/codecs (no dependency); 2 RunSource + verification (fixtures); 3 Neptune CSV; 4 Parquet reader (build-engineer); 5 Dynamo loader + G-ID/G-EV; 6 vectors; 7 SDK adapters (build-engineer); 8 load report and read-only cleanup inventory.
- Dependencies requested: parquet-hadoop 1.13.1 plus hadoop-client-api/runtime (ledger 3.4.1), scope Optional (or Provided) so they do not pass to rag/services; AWS SDK v2 BOM with s3, dynamodb, s3vectors, neptunedata at Compile; tests stub SDK interfaces. Later: `storageIT` configuration (build-engineer) and allowlist row activation (factory-engineer).
- Blocked items for later increments: domain-engineer additive StorageConfig keys (core has a single `vectorIndex`, ScholarChainConfig.scala L30-39); infra-engineer W1-W5; factory-engineer storageIT row.
- Cleanup procedure (W6): read-only inventory per run, move serving pointers, then vectors, DynamoDB items, Neptune, S3 prefixes, keep RunLedger and reports, inventory after; human only.
