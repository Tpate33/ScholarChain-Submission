# Race, memory and test-helper risk triage (orchestrator, 2026-11-20)

Per the human decision of 2026-11-20 (human-decisions-2026-11-20-closeout.md): no blanket deferral. Each risk is identified with its impact; anything that undermines integrity, idempotency or the local retrieval flow is assigned. Sources: CR-P7-03 residual risks, SE-P7-04 RISKS, Recording.scala as read.

| ID | Risk | Impact on integrity / idempotency / local flow | Decision | Owner, work order |
|---|---|---|---|---|
| T1 | Check-then-open race in `LocalRunSource` / `readVerified`: a swapped intermediate directory, hard link or FIFO between the path check and the open. | Content integrity holds: `readVerified` hashes the bytes it returns and compares them with `_parts.json`. Remaining impacts: a FIFO or device can block or exhaust the reader (local flow availability); a swapped directory makes the reader open a file outside the run directory, whose bytes are discarded on hash mismatch. | FIX (cheap): open with NOFOLLOW_LINKS and refuse anything that is not a regular file at open time (attributes read from the opened channel, not the path); bound the read by the manifest byte count + 1 so an oversized or endless stream is refused without unbounded reads. Tests: FIFO refused without blocking (where the OS allows creating one in a temp dir), oversized refused, symlinked intermediate directory refused. | storage-engineer, WP4 entry condition |
| T2 | Publication-row concurrency (CR-P7-03 R1): two loaders both see "unrecorded"; `firstLoadId` in the row body gives a false Conflict for loads of different stores. | Idempotency: without putIfAbsent-before-write, a concurrent rerun could duplicate writes; a false Conflict blocks a valid second-store load. | FIX in the first writer: putIfAbsent of the publication row before any data write; compare `partManifestSha256` (not the whole row) to decide same-run vs conflict; per-store load rows keyed by stable IDs. Test with two interleaved loaders on the fakes. | storage-engineer, WP5 (first writer) — WP4's graph loader also writes, so it applies there first |
| T3 | Memory: run bytes held up to maxFiles × maxTotalBytes; concurrent growth. | Since SE-P7-04 the verifier keeps only CSV bytes; `readVerified` reads one part at a time. Fixture is small; bounds are configuration with no defaults in main code. Local flow not affected. | NO CODE CHANGE beyond T1's per-read bound; record the bound in the WP7 load report and docs. Streaming is performance tuning (deferred by the human). | storage-engineer, WP7 (report); documentation-engineer, WP10 |
| T4 | Test helpers: `WriteCounts` has public mutable `var` fields (calls, written, alreadyPresent, failed); `RecordingKeyValueStore.byTable`, `RecordingVectorStore.batches` and `RecordingSleeper.sleeps` are public mutable collections/vars. These live in storage MAIN (`fake` package), so rag/services/tests code can use them. | Evidence integrity: any test (including later rag/services/tests code) can reset or set the counts, so a "zero writes" or "no new writes on rerun" assertion could be made true by mutation rather than behaviour. This directly weakens the idempotency evidence the retrieval flow will rely on. | FIX: make counters private with read-only accessors (or immutable snapshots); expose `byTable`, `batches`, `sleeps` as immutable views. Test: counters cannot be assigned from outside `fake` (`typeCheckErrors`). | storage-engineer, WP4 entry condition |
| T5 | `private[load]` reachable through a split package in another module (CR-P7-03 n3). | Another module could declare `package scholarchain.storage.load` and mint a `LoadPermit`, bypassing the gate. Only by deliberate code; storage's own test control suite uses it on purpose. | MITIGATE by review: code-reviewer checks every later diff for a foreign `scholarchain.storage.load` package; recorded for the whole-phase review (WP9). A build-level check would expand scanner scope, which the human deferred. | code-reviewer, WP9 |
| T6 | Parquet code is Optional scope, absent from the services runtime classpath (SE-P7-04). | Local flow: the fixture loader (WP7) runs from sbt where Optional is present, so the local flow works. Deployed loader packaging is deferred by the human (before deployment). | TRACK as part of the deferred deployed loader packaging; WP7 documents that the loader runs via sbt. | build-engineer (later, before deployment); WP10 docs |
